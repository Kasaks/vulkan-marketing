# Вулкан Маркетинг

Текущая тестовая версия главной страницы на **Astro 7.4.2**, без React и внешних UI-библиотек. Основа — выбранный рендер «Контрастная пауза»: светлая редакционная типографика, позиционирование на Авито, метрики, три формата сотрудничества, тёмный кейс, преимущества, этапы и прямые контакты.

## Запуск у себя

Откройте эту папку в VS Code. Для этой версии требуется Node.js 22.23.4+; Node.js 24 подходит. Нужная версия указана также в `package.json`.

В терминале в корне проекта:

```bash
npm ci
npm run dev
```

Откройте адрес, который покажет Astro, обычно `http://localhost:4321/`. Терминал оставьте работающим. Изменения в исходниках появятся в браузере после сохранения. Остановка — `Ctrl+C`.

Если PowerShell снова блокирует `npm.ps1`, используйте те же команды через `npm.cmd`: например, `npm.cmd ci` и `npm.cmd run dev`. Менять политику выполнения для этого не требуется.

## Что уже работает

- Светлая и тёмная темы. Выбор действует до перезагрузки страницы; cookies и хранилища браузера не используются.
- Мобильное меню с закрытием по ссылке, клику снаружи и Escape.
- Все кнопки «Обсудить задачу» открывают окно контактов. Из услуги можно перейти к нему напрямую.
- Форм, полей ввода, обработчика заявок и аналитических счётчиков нет.
- Четыре плитки метрик и один кейс из переданного наполнения. Старые учебные проекты и фиктивные заготовки отзывов удалены.
- Компонент галереи: главное фото, прокручиваемые миниатюры, полноэкранный просмотр, кнопки, стрелки клавиатуры и свайп. Закрытие крестиком, Escape или кликом по свободной области. На время просмотра страница зафиксирована; прокрутка мышью в галерее не листает фон.
- Пока массив `cases[0].images` пуст, показано место для скриншотов. Пустые контактные адреса и ссылки на отзывы не становятся активными ссылками.
- Основные тексты находятся в статическом HTML. Без JS полные описания услуг показываются ниже страницы, а контакты остаются в разделе контактов.

Ссылки на мессенджеры и профили Яндекса, а также фотографии кейса в документе не указаны. Интеграция отзывов ещё не подключена: сейчас подготовлены два места для источников, без вымышленных текстов, оценок и внешних виджетов. Блог остаётся отдельным этапом и не добавлен в меню. Порядок «услуги → тёмный кейс» сохранён по заметкам к макету, несмотря на повторяющуюся нумерацию в документе.

Подробнее о незаполненных данных и добавлении фотографий — в [docs/CONTENT.md](docs/CONTENT.md).

## Проверка сборки

```bash
npm run build
npm run verify
npm run preview
```

`dist/` — готовые файлы для статического хостинга. `preview` показывает именно собранную версию; откройте адрес из терминала. `verify` проверяет HTML тестовой версии: ссылки, локальные ресурсы, JSON-LD, наличие нового содержимого, отсутствие форм, синтаксис встроенных и внешних скриптов и запрет индексации. Это не замена визуальной проверке в браузере.

## Публикация на вашем хостинге

1. Сохраните резервную копию работающего сайта.
2. Соберите проект: `npm run build`.
3. Просмотрите его через `npm run preview`.
4. Загрузите **содержимое** `dist/` в согласованную папку сайта. `node_modules`, `src` и исходный `package.json` статическому хостингу не нужны.
5. Настройте на хостинге HTTPS и ответ HTTP 404 для `404.html`; проверьте главную и несуществующий адрес.

Конкретный хостинг и его пути из соседнего чата недоступны, поэтому они здесь не выдуманы. Если рабочий сайт уже существует, тестовую сборку сначала разместите на отдельном тестовом адресе.

## SEO и AI-поиск

Подробности и ссылки на официальные источники — в `docs/SEO.md`. Это свежая базовая реализация, а не подтверждение всех договорённостей из соседнего чата: получить его полную историю не удалось.

Сейчас включён `noindex`, а карта сайта не содержит тестовых URL. Подготовка к индексации: заменить демо-содержание, указать реальный домен в `.env` (`SITE_URL`), изменить `demoMode` на `false` в `src/data/site.ts` и выставить `SITE_INDEXABLE=true`, затем пересобрать. Не открывайте для индексации вымышленные данные и черновые цены.
